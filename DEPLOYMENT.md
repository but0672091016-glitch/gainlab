# Тестовое размещение GainLab

## Рекомендуемая платформа

Для текущей архитектуры рекомендуется **Netlify Free**. Проект использует полноценный Next.js с App Router, серверным получением спортивных новостей, кешированием, `next/image`, Cache Components и Partial Prerendering. Netlify поддерживает эти возможности через свой адаптер Next.js без перевода приложения в статический экспорт.

**Cloudflare Pages** сейчас подходит только для статического экспорта Next.js. Такой переход потребовал бы менять архитектуру и лишил бы текущий сайт серверного новостного дайджеста. Если в будущем будет выбран Cloudflare, для этой архитектуры следует рассматривать **Cloudflare Workers с Vinext**, а не Pages, и отдельно проверить совместимость перед миграцией.

## Что уже подготовлено

- `netlify.toml` фиксирует production-сборку `pnpm db:generate && pnpm build`, Node.js 22 и защиту от несовпадения версий клиентских ресурсов между публикациями. Явный шаг генерации нужен и при восстановлении кеша Netlify, когда `postinstall` может не выполниться повторно.
- `packageManager` фиксирует pnpm 11.25.0; Netlify определит pnpm по `pnpm-lock.yaml` и установит указанную версию через Corepack.
- `postinstall` генерирует Prisma Client при чистой установке зависимостей. Сгенерированные файлы по-прежнему не хранятся в Git.
- `engines.node` документирует минимальную версию Node.js 20.9, требуемую установленной версией Next.js.
- Производственная сборка не зависит от запущенного локального Docker-контейнера: без `DATABASE_URL` витрина использует `lib/demo-data.ts`, а при наличии переменной получает активный каталог из PostgreSQL.

## Как публикуются следующие изменения

1. Перед отправкой изменений выполнить `pnpm check`.
2. Создать коммит без секретов, `.env` и локальных сборочных файлов.
3. Отправить коммит в ветку `main` репозитория `but0672091016-glitch/gainlab`.
4. Netlify автоматически установит зависимости, сгенерирует Prisma Client, выполнит `pnpm build` и обновит production-сайт после успешной сборки.
5. Проверить главную страницу, каталог, подменю, поиск, новости, мобильную версию и внешние ссылки по публичному адресу.
6. При необходимости задать `NEXT_PUBLIC_SITE_URL` в настройках Netlify. Текущий код эту переменную пока не использует.

Для нынешней демоверсии `DATABASE_URL` на Netlify **не требуется**: код уже поддерживает PostgreSQL, но при отсутствии переменной сохраняет нынешний встроенный каталог. Не следует переносить на хостинг локальную строку подключения из `.env.example`.

## Как включить каталог из базы

Для активации уже подготовленного источника PostgreSQL понадобится:

1. создать управляемую PostgreSQL-базу, доступную из интернета;
2. сохранить production-значение `DATABASE_URL` только в переменных окружения хостинга;
3. выполнить `pnpm exec prisma migrate deploy` с production-строкой подключения;
4. для тестовой базы отдельно выполнить `pnpm db:seed`, который создаст 4 категории, 15 разделов и 32 явно тестовых товара;
5. повторно проверить поведение серверных функций и лимиты подключений базы.

Локальный PostgreSQL из `docker-compose.yml` предназначен только для разработки и не разворачивается на Netlify.

## Локальная проверка перед публикацией

```powershell
pnpm install --frozen-lockfile
pnpm check
```

Успешный `pnpm check` подтверждает типы, ESLint, автоматические тесты и production-сборку. Он не заменяет проверку Deploy Preview и реальный прогон миграции/seed в целевой базе.

## Ограничения бесплатного теста

На актуальном тарифе Netlify Free доступно 300 кредитов в месяц с жёстким лимитом. При исчерпании лимита проекты приостанавливаются до следующего расчётного периода; автоматических списаний на бесплатном тарифе нет. Этого достаточно для малопосещаемой тестовой версии, но не следует считать бесплатный тариф готовой производственной инфраструктурой.
