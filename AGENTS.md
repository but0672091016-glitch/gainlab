# AGENTS.md

## Назначение проекта

GainLab — MVP украинского интернет-магазина спортивного питания, товаров, одежды и аксессуаров. Интерфейс ориентирован на рынок Украины, использует украинский язык и гривну; тестовая версия опубликована на Netlify и также запускается локально.

Перед каждой новой задачей необходимо прочитать `AGENTS.md` и `PROGRESS.md`.

## Текущий этап

Разработка выполняется строго по этапам. Этап 1 завершён. В этапе 2 реализованы демонстрационная витрина, страницы товаров, общая локальная корзина, тестовое оформление и серверный источник каталога PostgreSQL с безопасным возвратом к встроенным демо-данным. Проект подготовлен к автоматическому созданию управляемой тестовой базы Netlify Database при публикации.

## Технологии и архитектура

- Next.js 16.4 с App Router и TypeScript.
- React 19.3.
- Tailwind CSS 4.
- PostgreSQL 17 через Docker Compose.
- Prisma ORM 7.10 с драйвером `@prisma/adapter-pg`.
- Локальная разработка через pnpm 11.25.
- Серверные маршруты Next.js находятся в `app/`; интерактивная главная вынесена в клиентский компонент.
- Демонстрационный каталог имеет двухуровневую иерархию `категория → раздел`; выбранные значения передаются через параметры `category` и `section`, а интерактивная фильтрация выполняется в клиентском компоненте.
- `lib/catalog-data.ts` является единым серверным источником каталога: при наличии локального `DATABASE_URL` или созданного Netlify значения `NETLIFY_DB_URL` он читает активные категории, разделы, бренды, товары и варианты через Prisma; при отсутствии подключения или ошибке возвращает `lib/demo-data.ts`, не ломая витрину.
- Страницы товаров используют динамический маршрут `app/product/[slug]`; известные демо-slug предварительно генерируются, а данные страницы, меню и каталога берутся из единого источника.
- Общая шапка магазина и демонстрационная корзина подключены в корневом layout и получают тот же каталог, поэтому навигация, поиск и ручное открытие корзины доступны на всех страницах; содержимое корзины сохраняется в `localStorage` браузера.
- Тестовое оформление реализовано отдельным маршрутом `/checkout`: клиентская форма передаёт контактные данные и состав корзины в Netlify Forms через статическую цель `/__forms.html`. PostgreSQL-заказ и онлайн-оплата при этом не создаются.
- Для форматированных украинских писем Netlify Forms отправляет новые заявки `gainlab-order` в опубликованное Google Apps Script web app. Скрипт проверяет webhook-секрет, экранирует поля, блокирует повторную отправку по `submission.id` и отправляет HTML-письмо через Gmail. Ответ webhook возвращается через `HtmlService`, чтобы Netlify не считал перенаправление `ContentService` ошибкой доставки. Получатель и секрет хранятся только в Script Properties.
- Спортивные новости загружаются на сервере из разрешённого списка украинских источников, кешируются средствами Next.js и передаются в клиентскую главную как сериализуемые данные.
- Prisma Client генерируется в `app/generated/prisma` и не хранится в Git.
- Для бесплатной тестовой публикации без изменения архитектуры используется Netlify; конфигурация хранится в `netlify.toml`. Production-сборка автоматически запускается из ветки `main` GitHub-репозитория `but0672091016-glitch/gainlab`. Cloudflare Pages не используется, поскольку текущий сайт требует серверного выполнения Next.js.

## Развёртывание

- GitHub: `https://github.com/but0672091016-glitch/gainlab`.
- Публичный тестовый сайт: `https://magical-belekoy-ed4358.netlify.app`.
- Netlify-проект: `magical-belekoy-ed4358`; production-ветка — `main`.
- Сборка: `pnpm db:generate && pnpm build`, каталог публикации, определённый адаптером Next.js, — `.next`, Node.js — 22. Явная генерация Prisma обязательна, поскольку Netlify может восстановить кеш зависимостей без повторного `postinstall`.
- Официальный пакет `@netlify/database` включает автоматическое создание управляемой PostgreSQL-базы Netlify Database. Netlify сохраняет строку подключения как `NETLIFY_DB_URL`; вручную копировать её в репозиторий нельзя.
- Перед публикацией Netlify автоматически применяет SQL-файлы из `netlify/database/migrations/`. Начальная схема там должна оставаться идентичной соответствующей Prisma-миграции, а последующие изменения схемы необходимо отражать в обеих системах миграций.
- Тестовые заявки принимает Netlify Forms под именем `gainlab-order`. Для формы настроен исходящий HTTP POST webhook в Google Apps Script; адрес получателя и webhook-секрет не хранятся в репозитории. Стандартное email-уведомление Netlify отключено после подтверждённой доставки нового письма.

## Структура проекта

- `app/page.tsx` — серверная точка входа главной страницы.
- `app/layout.tsx` — корневой layout, метаданные и подключение общей шапки с провайдером корзины.
- `app/globals.css` — Tailwind, дизайн-токены и общие визуальные эффекты.
- `app/catalog/page.tsx` — серверная точка входа каталога и граница `Suspense` для параметра категории.
- `app/checkout/page.tsx` — серверная точка входа тестового оформления и метаданные страницы.
- `app/product/[slug]/page.tsx` — серверная динамическая страница товара со статической генерацией тестовых slug.
- `app/info/[slug]/page.tsx` — заготовки информационных и юридических страниц.
- `components/store-header.tsx` — общая адаптивная шапка магазина: поиск, основная навигация, подменю каталога и кнопка корзины.
- `components/home-storefront.tsx` — интерактивная главная: товарные вкладки, спортивный дайджест, категории и тестовое избранное.
- `components/catalog-storefront.tsx` — клиентская витрина каталога: карточки, поиск, категории, сортировка, тестовые избранное и корзина.
- `components/product-detail.tsx` — клиентская карточка товара: вариант, количество, тестовые избранное и корзина, характеристики и похожие позиции.
- `components/demo-cart.tsx` — общий клиентский провайдер и выдвижная панель тестовой корзины.
- `components/demo-checkout.tsx` — клиентская форма тестового оформления, сводка корзины и URL-encoded отправка тестовой заявки в Netlify Forms; локально отправка имитируется без сетевого запроса.
- `lib/demo-data.ts` — явно тестовые категории, разделы каталога и товары с проверяемой привязкой к обоим уровням иерархии.
- `lib/catalog-data.ts` — серверный выбор PostgreSQL или безопасного демо-источника.
- `lib/catalog-mapper.ts` — проверяемое преобразование записей Prisma в существующий контракт витрины.
- `lib/demo-cart.ts` — чистые операции добавления, объединения, изменения количества и удаления строк тестовой корзины.
- `lib/sports-news.ts` — получение, проверка, нормализация и кеширование заголовков спортивных новостей.
- `prisma/schema.prisma` — схема категорий, разделов, брендов, товаров, вариантов, баннеров, поставщиков и истории синхронизации.
- `prisma/migrations/` — начальная миграция PostgreSQL.
- `prisma/seed.ts` — заполнение всей тестовой иерархии и 32 товаров для локальной или отдельной тестовой базы.
- `netlify/database/migrations/` — автоматически применяемые Netlify миграции схемы и тестового каталога.
- `scripts/render-netlify-seed.ts` — генератор SQL seed-миграции Netlify из единственного набора `lib/demo-data.ts`.
- `prisma.config.ts` — конфигурация Prisma CLI.
- `docker-compose.yml` — локальный PostgreSQL.

- `integrations/google-apps-script/Code.gs` — исходник webhook-обработчика, формирующего украинское HTML-письмо с таблицами клиента, доставки и товаров.

## Постоянные технические и продуктовые решения

- Все видимые пользовательские тексты — на украинском языке.
- Фирменные цвета: `#0B0D0E`, `#171B1D`, `#B6FF00`, `#FFFFFF`, `#F5F6F7`.
- Использовать предоставленный логотип. Не заменять его текстом и не генерировать новый.
- Демо-товары, цены, скидки и остатки всегда явно помечать как тестовые.
- Не добавлять вымышленные отзывы, рейтинги, реквизиты, гарантии, сроки доставки или условия возврата.
- Не хранить секреты в исходном коде. Новые переменные добавлять в `.env.example` без реальных значений.
- Для локальной или сторонней PostgreSQL использовать `DATABASE_URL`; в Netlify принимать автоматически созданную `NETLIFY_DB_URL`. Не публиковать значения обеих переменных.
- Постоянные данные должны проектироваться под PostgreSQL; временное клиентское состояние допустимо только для демонстрации ещё не реализованных этапов.
- До появления учётных записей тестовая корзина хранится только в `localStorage`; она не является серверным заказом и не синхронизируется между устройствами.
- Браузеры и устройства без авторизации считаются разными покупателями. Планируемое оформление должно поддерживать два самостоятельных сценария: быструю покупку без обязательной регистрации и покупку через учётную запись. Синхронизацию корзины между устройствами предусматривать только для авторизованного покупателя.
- Пока серверное оформление не реализовано, форма `/checkout` должна явно оставаться тестовой: предупреждать о передаче контактов в Netlify Forms, требовать согласие, не имитировать реальный номер заказа и не запрашивать платёжные реквизиты. Корзину очищать только после успешной передачи.
- Email получателя заявок не добавлять в клиентский код. Менять его только в Google Apps Script `GAINLAB_RECIPIENT`. Это позволяет перейти на доменную почту без правки приложения.
- Не возвращать ответ Netlify webhook через Google Apps Script `ContentService`: его перенаправление может вызвать повторные доставки и автоматическое отключение webhook после шести ошибок. Использовать `HtmlService` и после изменения проверять один вызов на одну контрольную заявку.
- Для поставщиков сохранять отдельные сущности, внешние идентификаторы и историю синхронизации.
- Не подключать платные сервисы и реальные платёжные данные на текущем этапе.
- Не публиковать сайт и не менять настройки внешнего хостинга без отдельного запроса пользователя.
- В новостном дайджесте показывать только заголовок, дату, категорию, источник и ссылку на оригинал; не копировать полный текст или изображения материалов.
- Новостные URL принимать только с явно разрешённых HTTPS-доменов источников. Недоступность одного источника не должна ломать главную страницу.

## Правила изменений

1. Сначала проверить фактическое состояние проекта и `PROGRESS.md`.
2. Не удалять пользовательские файлы и не переписывать данные без согласования.
3. Не выдавать заглушки или требования за завершённые функции.
4. Сохранять адаптивность и доступность: подписи элементов, клавиатурный фокус, контраст и поддержку `prefers-reduced-motion`.
5. После значимой задачи обновлять `PROGRESS.md`.
6. При изменении архитектуры, команд или постоянных правил обновлять этот файл.
7. Не переписывать историю прогресса без необходимости.
8. Если информации недостаточно, прямо указывать это.
9. При изменении Prisma-схемы создавать согласованные миграции в `prisma/migrations/` и `netlify/database/migrations/`; тест должен подтверждать совпадение общей начальной схемы.

## Сборка и тестирование

Из корня проекта:

```powershell
pnpm install
pnpm db:generate
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

Полная проверка без базы: `pnpm check`.

Локальный запуск интерфейса: `pnpm dev`.

База данных после установки Docker Desktop:

```powershell
Copy-Item .env.example .env
pnpm db:up
pnpm db:migrate --name init
pnpm db:seed
pnpm db:studio
```

Если Docker недоступен, это не мешает просмотру главной страницы, но миграции и seed нельзя считать проверенными.
